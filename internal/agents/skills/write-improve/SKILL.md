# 小说章节改稿优化技能 | 出版级中文小说精准改稿
## 【最高优先级】不可突破的改稿红线规则
> 以下规则为绝对硬约束，优先级高于所有改稿要求、评审建议，违反任意一条改稿即为无效。本规则与配套的「生成技能」「评审技能」标准100%统一，确保全流程闭环。
1.  绝对不篡改、不违背既定核心设定：所有修改不得突破`story_setup`的世界观/类型/主题/视角/时态、`chapter`的全部情节节点（beat）、`continuity`的全局故事状态、`recap`的既定剧情、`next_chapters`的后续走向，杜绝改稿导致吃书、情节节点遗漏、核心剧情偏移。
2.  绝对保证人设零崩塌（OOC）：所有修改不得改变人物既定性格、行为逻辑、对话声线、核心动机，禁止为了适配修改建议出现不符合人设的内容。
3.  绝对100%响应评审分级建议：必须按优先级完整落地评审给出的所有修改建议，不得遗漏、无视合规的评审意见。
4.  绝对保留原稿核心优势：不得修改、删除原稿中评审明确标注的亮点、高光内容，改稿是优化升级，不是推翻重写。
5.  字数绝对合规：改稿后最终字数必须保持在`target_words`的±5%误差范围内，不得因修改大幅超字或字数不足。
6.  幽默风格绝对稳定（如适用）：修改不得破坏原稿既定的幽默浓度档位、人设适配的笑点设计，禁止为了改稿删掉合规笑点、新增不符合人设/剧情的违和笑点，搞笑内容不得消解核心剧情张力。

## 核心目的
严格基于评审给出的分级修改建议，在不突破既定故事框架、不破坏原稿核心优势、不触碰改稿红线的前提下，对章节内容进行精准优化升级，最终输出符合出版级标准、完全匹配所有要求的优化后章节终稿。

## 强制参考输入项（所有字段必须纳入改稿依据，不得遗漏）
> 所有修改必须100%基于以下输入项，不得脱离给定信息做无依据修改，与「生成技能」「评审技能」输入体系完全统一。
- `story_setup`：故事核心设定，包含核心前提、故事类型、核心主题、叙事时态、视角规则、目标受众、整体文风基调、核心幽默风格要求，以及可选的`writing_style`写作风格要求
- `chapter`：单章核心信息，包含章节ID、章节标题、章节摘要、完整情节节点（beat）、开篇/收尾核心节点、节奏要求、出场人物、核心场景、可选的`chapter_payoff`爽点契约、本章指定幽默浓度档位（如适用）
- `continuity`：全局故事连续性上下文，包含人物当前状态、持有物品、人物关系、地图位置、生效的世界观规则、已解锁剧情节点等全部既定事实
- `target_words`：本章强制要求的目标字数
- `iteration`：当前改稿迭代轮次（1=初稿改稿，≥3=终稿打磨），与评审轮次完全对应
- `current_draft`：待优化的当前章节原稿全文
- `suggestions`：评审给出的分级修改建议（含致命优先级/高优先级/打磨优先级）
- `context`：剧情连续性上下文，包含前序章节完整内容、已确认的官方设定
- `recap`：上一章官方剧情复盘，用于校验改稿后开篇的承接连续性
- `next_chapters`：后续章节信息数组，确保改稿不破坏预埋伏笔、收尾钩子的合规性

## 改稿核心执行准则
1.  **全量响应评审建议**：严格按照「致命优先级→高优先级→打磨优先级」的顺序，完整落地每一条合规的修改建议，每条建议都必须有对应的修改落地，不得选择性无视。
    - **禁止替代方案**：不得自行构思替代方案来"圆上"或"解释"问题，必须严格按照评审建议的具体要求执行。例如：若建议要求"统一小石头的年龄为11岁"，则必须直接将"十二岁"改为"十一岁"，禁止添加时间铺垫来强行圆成12岁。
2.  **核心优势完整保留**：必须完整保留原稿中评审明确标注的亮点、高光情节、优秀对话、氛围感描写，不得因修改导致原有优势丢失，优化是锦上添花，不是推倒重来。
3.  **质量正向升级**：所有修改必须实现内容质量的提升，不能为了改而改，不能把通顺合理的内容改成生硬违和的版本，确保改稿后整体质量优于原稿。
4.  **出版级标准不降级**：改稿全程保持出版级写作要求，不得因修改出现语句不通、语法错误、错别字、节奏混乱、视角偏移等问题。
5.  **全剧情连续性零崩坏**：所有修改必须贴合故事整体设定、前序剧情、后续走向，不得出现前后矛盾、吃书、伏笔断裂、承接断层的问题。
6.  **文风基调100%统一**：修改必须完全贴合既定的整体文风，尤其是幽默风格的浓度、笑点设计逻辑，不得出现改稿后文风割裂、调性偏移的问题。
7.  **写作风格参照不污染剧情**：如果`story_setup.writing_style`存在，改稿应贴合其叙述声音、句式节奏、描写密度和对白质感；`reference_excerpt`只可作为文风参照，禁止复制原句，禁止导入其中的人物、地点、情节、设定或专有名词。
8.  **爽点契约必须落地**：如果`chapter.chapter_payoff`存在，改稿必须补强目标、阻力、聪明破局、爽点画面、赢后收益、旁人反馈和结尾钩子中缺失或偏弱的部分。只能在既定情节框架内增强呈现，不得新增违背大纲的能力、奖励或结果。

## 分级优化执行规则（与评审建议完全对应）
### 致命优先级（必须第一时间100%落地，迭代轮次1仅改此部分）
- 修正所有剧情逻辑错误、世界观设定崩坏、吃书等红线违规问题
- 修正所有人设崩塌、对话声线完全偏离、人物动机矛盾的问题
- 修正所有剧情连续性断裂、开篇承接错误、伏笔与后续剧情矛盾的问题
- 补全所有缺失、弱化的核心情节节点（beat），确保100%按要求落地
- 修正所有超出字数误差范围的大幅字数偏差问题

### 高优先级（致命问题修正后完整落地，迭代轮次2核心修改内容）
- 优化章节节奏失衡、情节拖沓/过快的问题，调整段落与内容占比
- 优化对话内容，提升辨识度、贴合人设，删除无效水对话，强化对话的剧情推动作用
- 优化场景描写，补充多感官细节，提升氛围感，删除冗余的说明文式铺垫
- 强化情绪感染力，优化高潮情节的张力、情绪名场面的共鸣感，修正情绪断层、调性违和的问题
- 优化开篇钩子与收尾钩子的吸引力，确保贴合前序剧情与后续走向
- 强化爽点兑现：把“主角怎么赢”写清楚，尤其是如何利用本书独特设定、规则边界、敌人误判或信息差。不要只增加危险或痛苦；要增加漂亮反制和可见收益。

### 打磨优先级（前两类问题全部修正后落地，迭代轮次≥3仅改此部分）
- 优化用词精准度，替换生硬拗口、不符合人设/文风的词语，避免重复用词
- 优化语句节奏与流畅度，调整句式结构，避免单调重复，提升阅读顺滑度
- 微调细节笑点，优化幽默内容的自然度，确保贴合人设与剧情节奏
- 修正错别字、标点错误、语句不通顺等细节问题
- 优化段落拆分，适配移动端阅读习惯，提升排版可读性

## 幽默风格改稿专项规则（如适用）
1.  改稿必须严格匹配本章指定的幽默浓度档位（轻度/中度/重度），不得因修改提升或降低既定浓度
2.  所有笑点修改必须严格贴合对应人物的人设，不得新增不符合人物性格的违和笑点，不得删除原稿中合规的人设适配笑点
3.  不得为了修改建议，在核心高潮、关键情绪名场面、严肃剧情节点硬塞笑点，消解剧情张力
4.  必须删除评审标注的违禁笑点（过时网络热梗、低俗烂梗、脱离故事背景的违和内容），替换为贴合设定、人设的合规笑点
5.  幽默内容的修改必须服务于剧情、人物塑造，不得为了搞笑新增与主线无关的水内容

## 输出强制要求
1.  必须返回有效 JSON，不得添加 markdown 代码块标记或其他说明文字
2.  JSON 顶层必须包含 `content` 字段，字段值为优化后的完整章节正文
3.  `content` 中禁止包含修改说明、改动对比、作者注释、元评论、改稿思路等任何非正文内容
4.  `content` 必须为纯小说正文，无特殊格式、无标记、无括号备注，仅保留叙事、对话、场景描写
5.  `content` 必须完整覆盖本章全部情节节点，开篇承接合规，收尾钩子完整，无内容截断

响应格式：
```json
{
  "content": "优化后的完整章节正文..."
}
```

## 改稿绝对禁止事项
1.  禁止为了适配修改建议，篡改、突破既定的核心设定、情节节点、故事走向
2.  禁止修改、删除原稿中评审明确标注的核心优势、高光内容
3.  禁止无视评审建议的优先级，先改细节打磨内容，不修正致命红线问题
4.  禁止改稿后出现人设崩塌、吃书、剧情连续性断裂、视角时态偏移等问题
5.  禁止输出任何正文以外的解释、说明、备注内容
6.  禁止改稿后字数超出目标字数±5%的误差范围
7.  禁止改稿后文风割裂、调性偏移，破坏故事整体的叙事风格
